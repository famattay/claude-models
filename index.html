¿Qué es "Investigación Profunda" (Deep Research)?

Deep Research es una capacidad exclusiva de Claude que automatiza un proceso investigativo análogo al de un analista humano dedicado. Mientras que una respuesta estándar entrega síntesis basada en el contexto proporcionado, Deep Research ejecuta múltiples búsquedas web, consulta fuentes heterogéneas, cruza información entre ellas, identifica inconsistencias, y compila un reporte estructurado con atribución de fuentes.

  • Duración: 5–10 minutos por investigación, ejecutada en segundo plano
  • Consumo de tokens: Alto (múltiples búsquedas + síntesis), consumidas contra tu cuota de research (separada de API tokens estándar)
  • Casos de uso: Análisis de mercado competitivo, síntesis de literatura académica, revisión de cambios regulatorios, benchmarking multi-jurisdiccional
  • Diferencia con Fable: Fable es capacidad pura de razonamiento sin acceso a búsqueda; Deep Research es búsqueda + síntesis automatizada

3. Árbol de Decisión: Qué Modelo Elegir

🎯 Selecciona por Restricción Primaria

¿La restricción es PRESUPUESTO?
→ Haiku 4.5
Razón: Costo 1x, suficiente para >95% de tareas de clasificación y extracción. Combina con prompt caching (reduce costo a 0.125x) si reutilizas el mismo contexto.
¿La restricción es LATENCIA?
→ Haiku 4.5 (sub-100ms) o Sonnet 5 (100-300ms)
Razón: Haiku es el más rápido; Sonnet casi tan rápido pero con mejor razonamiento para APIs de cliente donde percepto < 500ms.
¿La restricción es VOLUMEN (>50k solicitudes/mes)?
→ Haiku 4.5
Razón: Costo marginal domina; por cada million tokens ahorras $4 entrada y $20 salida vs Sonnet. En 50k solicitudes de 2k tokens entrada/500 salida = 100M entrada, 25M salida = ahorro de $400-500/mes.
¿No hay restricción clara o es la PRIMERA VEZ implementando?
→ Sonnet 5
Razón: Punto de equilibrio recomendado por Anthropic; suficiente para >90% de casos reales, mejor que Haiku en reasoning, más barato que Opus. Migra a Haiku si el volumen lo justifica; migra a Opus si la calidad lo justifica.
¿El problema es MAL DEFINIDO o requiere INVESTIGACIÓN?
→ Opus 5
Razón: Capacidad de razonamiento > Sonnet; maneja ambigüedad, infiere variables ocultas, genera hipótesis. Para análisis estratégico donde el enunciado es vago.
¿El error es INACEPTABLE (decisión de billones, litigio, salud)?
→ Opus 5 o Fable 5.1**
Razón: Mayor probabilidad de validez metodológica. Fable si tienes acceso (Project Glasswing) y costo no es factor limitante.
¿Necesitas DEEP RESEARCH (búsqueda + síntesis)?
→ Cualquier modelo + Deep Research activado
Razón: Deep Research es feature ortogonal a la capacidad del modelo. Úsalo con Sonnet para reducir costo; úsalo con Opus si necesitas síntesis de análisis complejos.

5. Estrategias de Reducción de Costo Efectivo

Técnica Ahorro Típico Cómo Aplicar Trade-off
Prompt Caching (5 min) 90% en tokens reutilizados Cachea system prompt + documento base que se reutiliza >2 veces. Primera solicitud paga 1.25x; siguientes pagan 0.1x. Requiere que el contexto sea estable. Efectivo para: análisis de múltiples preguntas sobre mismo documento.
Batch API 50% en tokens procesados Agrupa solicitudes no urgentes (procesamiento nocturno, análisis bulk). API ejecuta en 24h, factura 50% del costo estándar. Latencia de 24h; no apto para consultas interactivas. Excelente para: generación de reportes diarios, análisis histórico.
Routing inteligente 65% si 70% de solicitudes van a Haiku Evalúa solicitud con Haiku primero (rápido, barato). Si falla, reintenta con Sonnet. Así solo el 30% usa Sonnet. Latencia de reintento; complejidad de lógica. Excelente para: clasificación donde Haiku falla 20–30% de las veces.
Prompt Compression 20–40% en tokens entrada Elimina ejemplos redundantes, resume documentos previos, reduce verbosidad del system prompt sin perder funcionalidad. Riesgo de pérdida de información. Comienza comprimiendo ejemplos, luego resúmenes.
Batch + Cache combinado 95% potencial (50% batch × 90% cache hits) Envía lote de solicitudes vía Batch API donde cada una reutiliza caché. Ej: 100 preguntas sobre mismo documento, enviadas en batch. Complejidad máxima; requiere: contexto estable + procesamiento no urgente. Ideal para: análisis masivo de compliance.
